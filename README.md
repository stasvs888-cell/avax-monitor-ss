# AVAX Long-Only Monitor

Фоновый скрипт: раз в 5 минут (настраивается) тянет AVAX_USDT и BTC_USDT с
публичного API MEXC Futures, считает тренд/уровни/сетапы по твоей стратегии
(breakout / pullback, long-only) и шлёт в Telegram **только при смене
сигнала** (LONG SETUP / WAIT / NO LONG) — без спама каждую минуту.

Это не финансовый совет и не автотрейдинг — только оповещения. Ордера
скрипт не ставит.

## 1. Создать Telegram-бота

1. В Telegram напиши **@BotFather** → `/newbot` → следуй инструкциям.
2. Скопируй токен вида `123456:ABC-DEF...`.
3. Напиши своему новому боту любое сообщение (`/start`), иначе он не
   сможет писать тебе первым.
4. Узнай свой `chat_id`: напиши **@userinfobot** — он пришлёт твой ID.

## 2. Задеплоить на Railway

1. Зайди на [railway.app](https://railway.app), New Project →
   **Deploy from GitHub repo** (проще всего залить эту папку к себе в
   GitHub) либо **Empty Project** → загрузить файлы вручную через Railway CLI.
2. В настройках проекта → **Variables** добавь:
   - `TELEGRAM_BOT_TOKEN` — токен из шага 1
   - `TELEGRAM_CHAT_ID` — твой chat_id из шага 1
   - `CHECK_INTERVAL_SECONDS` — например `300` (5 минут)
3. Railway увидит `Procfile` и `requirements.txt` и сам поставит
   зависимости и запустит `python main.py` как worker-процесс.
4. Deploy → в логах должно появиться `AVAX monitor starting...`.

## 3. Проверить, что работает

В логах Railway (вкладка Deployments → View Logs) будет строка на каждой
проверке: `no change: WAIT` или `sent: LONG SETUP` и т.п. Первое сообщение
в Telegram придёт, когда сигнал реально изменится относительно момента
запуска.

## Что можно донастроить в `main.py`

- `VOLUME_CONFIRM_MULT` — насколько объём должен превышать средний для
  подтверждения пробоя (сейчас 1.2×)
- `LEVEL_TOUCH_PCT` — насколько близко цена должна подойти к уровню,
  чтобы считаться "у поддержки/сопротивления" (сейчас 0.3%)
- `BTC_DROP_ALERT_PCT` — просадка BTC за 3 последние 1H свечи, после
  которой BTC-фильтр становится "negative" (сейчас -1.5%)
- `PIVOT_LOOKBACK` — сколько свечей слева/справа нужно для подтверждения
  локального хая/лоу (сейчас 3)

Логика пробоя/отката упрощённая (проверяет закрытие 1H свечи + объём +
удержание), а не полный набор правил из твоей спецификации (ретесты,
ложные пробои, различение открытых/закрытых свечей уже учтено). Это
рабочая основа — при желании могу усложнить под конкретные случаи, которые
увидишь в реальной работе.
